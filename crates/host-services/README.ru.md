# Опциональные сервисы хоста

[English](README.md) | [Русский](README.ru.md) | [Документация](../../docs/ru/README.md)

По умолчанию crate собирает только общий реестр фабрик и владельца сервисов. У него нет зависимостей от рендера, оконной системы, игровых пакетов или платформенного воспроизведения. Включите `audio` и вызовите `install_audio` в профиле приложения, чтобы установить фабрику `audio.wav`.

Игровые пакеты обнаруживают значения `HostServiceRequest` в своём авторском расписании. Хост передаёт проверенные метаданные ID/пути ресурсов, корень ресурсов и свой атомарный флаг вывода из эксплуатации в `HostServiceRegistry::build`. При отключённом создании не появляется ни одного экземпляра сервиса и не вызываются фабрики, разрешение ресурсов, чтение файлов или платформенное аудио. Запрос, отсутствующий в исходном пакете, тоже не создаёт сервис. Включённый запрос недоступной фабрики завершается явной ошибкой.

`set_enabled(false)` заглушает уже созданные сервисы, сохраняя их ресурсы и логическую диагностику; он не отменяет первоначальную загрузку. Чтобы включить сервисы хоста, созданного с отключёнными сервисами, их нужно пересоздать. Простое переключение пустого владельца никогда не выполняет скрытый файловый ввод-вывод.

Конфигурация WAV содержит `cues` (имя сигнала → исходный путь относительно проекта или ссылка `asset://`), `event` и `cue_field`. Сопоставление событий задаётся конфигурацией, поэтому сервис не знает перечислений событий какой-либо игры. Совпадение с известным сигналом увеличивает логический диагностический счётчик `played` даже при выключенном звуке. Restart/reset обнуляет этот счётчик. Замена конфигурации сервиса создаёт нового владельца и перезапускает его диагностику; счётчики не являются сериализуемым состоянием игры.

На Windows воспроизведение использует существующий единственный асинхронный WAV-голос на весь процесс. Остановить его может только текущий владелец, а выведенный из эксплуатации актор не может начать последующее воспроизведение. Проверка владения и короткий native-вызов используют один mutex. Хост отдельно сигнализирует о выводе из эксплуатации через атомарный флаг; удаление кандидата, который ничего не воспроизводил, не может вывести принятый хост из эксплуатации или остановить голос другого владельца.

Сейчас `WAV_PLAYBACK_SUPPORTED` равен true только на Windows. В этой версии у Linux нет native-аудиоадаптера. Включённый запрос `audio.wav` завершается до файлового доступа к ресурсам явным сообщением о неподдерживаемой платформе; он не может сообщить об успешном воспроизведении через пустую реализацию. Отсутствующий запрос или хост, созданный с отключёнными сервисами, остаётся допустимым на Linux. Проектам без звука (включая Empty и Puzzle) аудиосервис не нужен. Чтобы запустить проект с аудиосигналами без воспроизведения на Linux, явно отключите сервисы или используйте профиль без этих сигналов; загрузка Windows-аудиозависимости не добавляет звук на Linux.

Поле `played` остаётся логическим счётчиком совпавших сигналов, включая заглушённые; `platform_playback` описывает возможности адаптера, а не слышимый вывод устройства. Ошибки запуска native-воспроизведения передаются владеющему хосту и не передают неудачному кандидату владение общим голосом процесса.
