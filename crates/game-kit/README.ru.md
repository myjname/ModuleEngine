# Чистые модули для создания игр

[English](README.md) | [Русский](README.ru.md) | [Архитектура](../../docs/ru/architecture.md)

`module-engine-game-kit` предоставляет переиспользуемые Rust-библиотеки с
независимым выбором возможностей через features. Пакет не зависит от Core, ECS,
редактора, рендерера, нативных сервисов или конкретной игры. По умолчанию ни одна
возможность не включена.

```toml
module-engine-game-kit = { path = "../game-kit", default-features = false, features = ["grid", "history", "campaign", "actions"] }
```

Это библиотечные модули, а не исполняемые системы графа или нативные сервисы.
Выбор Cargo feature открывает API; он не устанавливает узел графа, не создаёт
состояние, не запускает аудиоустройство, не читает сохранение и не активирует игру.
Пакет-потребитель вызывает API из реальных систем/UI/инструментов и владеет
соответствующими контрактами композиции, схем, состояния и сервисов. Не добавляйте
фиктивные системы в расписание только для отображения этих библиотек в графе.

## Сетка

`grid::Cell { x, y }` — целочисленная координата. `GridBounds::new(width, height)`
отклоняет нулевые размеры и размеры за пределами положительного диапазона `i32`.
Десериализация повторяет эту проверку. `contains` проверяет полуоткрытый
прямоугольник `[0, width) × [0, height)`; `Cell::offset` проверяет переполнение.

`Occupancy<Layer, Id>` — временный проверенный индекс. Каждый ID встречается
один раз, а в каждой паре `(Cell, Layer)` находится не больше одного объекта.
Разные слои могут перекрываться; библиотека не задаёт слоям встроенные правила
столкновений или игровую семантику.

- `insert(cell, layer, id)` отклоняет дубликаты и координаты за границами.
- `get(cell, &layer)`, `position(&id)`, `layer(&id)` и `entries()` читают индекс.
- `relocate(&[(id, destination)])` проверяет весь пакет перед публикацией.
  Перестановки разрешены; неизвестные/повторные ID, столкновения и координаты вне
  сетки сохраняют исходный индекс. Пустые пакеты и переносы без изменений допустимы.
- `remove(&id)` удаляет только указанный объект.

Потребители сериализуют собственные авторские записи/сохранения и восстанавливают
из них индекс. Он намеренно не является вторым сериализованным владельцем этих
данных. Правила поверхности, толкания, перемещения и целей проверяет потребитель
перед вызовом переноса.

`GridProjection::new(bounds, origin, cell_size)` отображает центры на произвольную
двумерную плоскость. `origin` — центр клетки `(0, 0)`; трёхмерный потребитель может
использовать плоскость как мировую XZ и отдельно задавать высоту. `cell_center`
отклоняет клетки вне сетки. `cell_at` возвращает ближайшую клетку в пределах сетки,
включает её нижнюю границу, исключает верхнюю и возвращает `None` для неконечных
координат/позиций вне сетки. Параметры проекции и крайние выходные позиции должны
быть конечными. Выход использует `f32` для совместимости с UI/рендерером: большие
вещественные координаты приблизительны, а `Cell` остаётся точным логическим
владельцем координат.

Тесты покрывают переносы на многослойном поле, атомарный отказ и тактическое
построение с перестановкой юнитов на наземном/воздушном слоях и проекцией для рисования.

## История

`history::UndoJournal<T>` хранит текущее принятое состояние и прошлые состояния,
начиная с самого старого. `commit(next)` возвращает `false` для равного кандидата
без изменений; иначе переносит предыдущее текущее состояние в историю. Потребитель
должен вызывать его только после принятия операции. `undo()` восстанавливает
предыдущее состояние и возвращает ссылку либо `None`, если история исчерпана.
Новый commit после Undo начинает новую ветвь; API Redo отсутствует.
`reset(initial)` очищает весь журнал.

Журнал сериализует `current` и `past`, включая все состояния Undo. Фиксированного
ограничения длины истории нет. Ограничения памяти и сериализованного входа относятся
к границе потребителя/хранилища. `validate(callback)` проверяет каждое прошлое и
текущее состояние перед принятием восстановленных данных; универсальная
десериализация не может проверить игровые правила payload. Состоянием может быть
непрозрачный JSON, сохраняющий любые принадлежащие потребителю поля.

Тесты покрывают 2048 принятых ходов с сохранением/восстановлением и Undo, отклонение
неверного старого состояния и независимый документ рисунка с ветвлением после Undo.

## Кампания

`campaign::Campaign<Attempt>::new(level_ids, ScoreOrder)` владеет упорядоченным
непустым каталогом уникальных стабильных ID, одним текущим уровнем, границей
последовательного открытия, лучшими оценками `u64` и одной непрозрачной текущей
попыткой. Первый уровень изначально открыт. `LowerIsBetter` подходит для числа
ходов/времени; `HigherIsBetter` — для очков. Модуль не интерпретирует содержимое
уровней или данные попытки.

- `select(id)` отклоняет неизвестные/закрытые ID. Смена уровня очищает единственную
  текущую попытку; выбор того же уровня сохраняет её.
- `complete(score)` записывает лучшую оценку и открывает не более одного
  следующего уровня. Возвращает `Completion { new_best, newly_unlocked }`,
  сохраняет текущий выбор/попытку и не переключает уровень автоматически.
  Повторное прохождение раннего уровня не пропускает открытия и не ухудшает рекорд.
- `current`, `levels`, `unlocked_count`, `is_unlocked` и `best` читают состояние.
- `set_attempt`, `attempt`, `clear_attempt` управляют непрозрачной текущей попыткой;
  она может содержать `UndoJournal` и игровые позиции/счётчики.

Десериализация отклоняет неверные ID, записи прохождения не в виде начального
префикса уровней, несогласованное число открытий и закрытый/недопустимый текущий
уровень. Перед принятием сохранения потребитель также вызывает
`validate_catalog(authored_ids)` и `validate_attempt(callback)`. Сравнение каталога
сохраняет точный порядок/ID; изменения контента требуют явной миграции потребителя.
Окружающий формат сохранения владеет версией и идентичностью контента/схемы.
Действие Restart обычно очищает или заменяет попытку, сохраняя кампанию; это
решение принадлежит игре-потребителю.

Тесты покрывают оценки по ходам, выбор закрытого уровня, повторное прохождение,
сохранение попытки и гоночный сезон с очками, включая завершение последнего этапа.

## Действия

`actions::ActionMap::new(action_names, bindings)` проверяет уникальные непустые
имена действий и привязки физических клавиш и отклоняет ссылки на необъявленные
действия. Имена физических клавиш — непрозрачные стабильные строки, интерпретируемые
адаптером платформы. У одной клавиши одна привязка; несколько клавиш могут вызывать
одно действие. Действие без физической привязки доступно экранным элементам
управления. Десериализация повторяет те же проверки.

`Binding { key, action, trigger }` использует `Trigger::Pressed` или `Trigger::Held`.
Адаптер платформы передаёт упорядоченные записи `PhysicalEvent::Pressed(key)`,
`Released(key)` и `Repeated(key)` в
`map.evaluate(&mut ActionState, events, focused)`. Pressed для уже удерживаемой
клавиши не создаёт повторного нажатия. Повторы ОС должны использовать `Repeated`;
они могут восстановить удержание после возврата фокуса, но не создают нажатий.
Кадры без фокуса очищают состояние и игнорируют события. Неизвестные клавиши не
увеличивают сохраняемое состояние. При замене привязок вызывайте
`ActionState::reset`, если удерживаемые клавиши тоже должны сброситься.

Результат `ActionFrame { pressed, held }` сохраняет порядок событий нажатия и
устраняет дубликаты имён удерживаемых действий. Несколько свежих нажатий могут
повторить действие за кадр; очередью и правилом одного действия за тик владеет
игра/host. `named_press(action)` проверяет экранную кнопку в том же пространстве
имён и создаёт одно нажатие. `ActionFrame::extend` объединяет результаты UI и
физических клавиш, не меняя физическое удержание. Потребитель адаптирует результат
к Core `GameInput`; эта библиотека не зависит от Core или egui.

Тесты покрывают пошаговое управление/равенство экранной кнопке, повторы/порядок
событий, неверные привязки, сериализацию и независимый контроллер полёта с
удержанием тяги/потерей фокуса.

## Маршруты проверки

Эти команды описывают проверки пакета; они не подтверждают нативный звук/рендеринг,
интеграцию редактора, завершённость игры или измеренный FPS:

```powershell
cargo test -p module-engine-game-kit --all-features
cargo check -p module-engine-game-kit --no-default-features
cargo check -p module-engine-game-kit --no-default-features --features grid
cargo check -p module-engine-game-kit --no-default-features --features history
cargo check -p module-engine-game-kit --no-default-features --features campaign
cargo check -p module-engine-game-kit --no-default-features --features actions
```
