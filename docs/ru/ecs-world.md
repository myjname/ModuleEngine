# ECS-хранилище игрового мира

[English](../ecs-world.md) | [Русский](ecs-world.md) | [Документация](README.md)

`GameState.world: EcsWorld` — изменяемый игровой мир. Стабильные авторские ID индексируют
Transform, Parent, Color, динамические колонки компонентов и именованные ссылки. Отдельной
изменяемой карты сущностей, которую нужно синхронизировать с ним, нет. Этот этап проходит
проверку; статус приёмки см. в `modular-runtime-progress.md`.

## Доступ модулей

Native-системы выбирают состав сущностей до чтения значений:

```rust,ignore
let world = &context.world("world")?.world;
for id in world.entities_with(&["example.spin"]) {
    let settings = world.component(id, "example.spin").unwrap();
    let object = world.object(id).unwrap();
    // Stage portable WorldCommands, or edit a component in this tick's world.
}
```

`entities_with` пересекает колонки компонентов, начиная с самой маленькой,
и возвращает стабильный порядок ID. Пустой набор требований выбирает все сущности. Динамические
значения остаются JSON, описанным зарегистрированными схемами компонентов; это не
типизированная archetype ECS и не планировщик параллельных запросов.

`component_mut`, `insert_component`, `remove_component`, `transform_mut` и
`references_mut` изменяют канонический мир. Native-система может подготовить промежуточные
значения, но весь tick должен пройти структурную проверку, проверку ссылок и активных схем
до публикации. `upsert_entity` заменяет полный граничный DTO,
не начиная новую жизнь объекта; его ссылки проверяются на
границе публикации, что позволяет пакету создавать взаимно ссылающиеся объекты.

`entities_snapshot` и `entity` возвращают владеющие данными DTO `GameEntity` для Inspector,
сериализации, IPC и валидации. Изменение такого DTO не меняет мир.
Примените его явно или отправьте команды. Native hot loops используют запросы по колонкам.

## Время жизни и транзакции

Удаление поддерева очищает колонки и исходящие ссылки каждого удалённого объекта.
Сохранившиеся ссылки на удалённые цели блокируют публикацию, пока не будут явно
очищены. Удаление и создание того же ID начинает новую жизнь: старые компоненты,
ссылки и демонстрационная угловая скорость не могут попасть в заменяющий объект.

`lifetime(id)` обозначает текущую runtime-инкарнацию отдельно от
сохранённого ID. Клонирование checkpoint сохраняет её; создание, восстановление из DTO или
очистка и повторное создание объекта дают новый токен. Кеши модулей используют этот
токен, чтобы отбрасывать cooldown и death markers объекта при повторном использовании ID. Токены —
локальные для процесса служебные данные, исключённые из семантического сравнения миров и сохранённого
формата DTO сущности; это не дескрипторы для автора.

Намерения текущего tick и начальные позиции столкновений также содержат инкарнацию.
Исходная система, вставленная между авторскими этапами, может заменить объект, поэтому эти
временные записи не могут безопасно использовать только его сохранённый ID. Зафиксированные боевые визуальные эффекты
сохраняют исходную роль/стиль, а запросы целей или вспышки попаданий не привязывают
предыдущее действие к заменяющей сущности.

Исполнитель сохраняет checkpoint полного мира вместе с переносимым состоянием систем,
ресурсами и событиями. Custom Rust получает IPC DTO и возвращает команды; эти
команды применяются к ECS-кандидату до принятия управляющих значений renderer и состояния worker.
Неудачные кандидаты сохраняют ранее принятое состояние.

У ECS-сессии по умолчанию нет второго provider. Object-миры и явно
зарегистрированные сторонние миры остаются совместимыми проекциями переносимых данных
объектов. Их validation/commit/rollback по-прежнему участвуют в публикации, а
их частные кеши сохраняются между обычными tick. Новые игровые возможности относятся к
канонической ECS.

## Совместимость сохранений

Wire-представление `GameState` по-прежнему использует карту `entities` от стабильных ID
к DTO. Десериализация проверяет повторяющиеся ID, совпадение ключа карты с ID объекта,
иерархию, конечность transform и именованные ссылки перед созданием колонок.
Авторские сцены и prefab-записи сохраняют прежний формат. Этот snapshot-
адаптер не создаёт второго владельца живого игрового мира.
