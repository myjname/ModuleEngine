Тридцать три защищённых файла/артефакта и глобальная конфигурация Codex пользователя также сравнивались с начальными хешами.

Внедрение меняет инструкции ассистента, помощник чтения отчётов, проектный skill и настройки подзадач. Production-код движка, Cargo-зависимости и авторские данные проекта не меняются. Python-fixtures и проверки навигации не являются приёмкой движка, GPU, упаковки или опубликованных EXE.

Проверка выявила неоднозначность о ненужных правках уже правильного перевода; обе инструкции уточнены. Проверки относительных ссылок, структуры заголовков EN/RU и сохранности прошли. Это проверка примеров поведения, а не гарантия каждого будущего ответа.

Ассистенту разрешён выбор поддерживаемых настроек для делегированной работы. [Правила выбора](assistant-workflow.md#адаптивная-конфигурация-задач) используют low для узкого поиска, medium для ограниченной обычной работы, high для независимого ревью или сложной/чувствительной к данным задачи, более высокие поддерживаемые уровни — при обоснованной необходимости. В этом внедрении действительно использованы явные запуски low, medium и high. Текущий родительский turn не может изменить назначенные ему настройки через запуск подзадачи. ## Настройка Serena и успешные проверки

Пилот использовал коммит Serena [`d9e4c796fae0207ba6848d1df4b331122a5567b5`](https://github.com/oraios/serena/tree/d9e4c796fae0207ba6848d1df4b331122a5567b5), установленный как `serena-agent 2.0.1.dev0` в отдельное окружение Python 3.12.14 внутри игнорируемых файлов задачи. SHA-256 скачанного архива исходников — `7d8aafe15e9741c4ccedc26473cfd25a27f379f38c31c3f13135f06e9f5c482f`. Коммит установленного архива подтверждён закреплённым скачиванием, а не суффиксом версии, который может относиться к Git-ревизии рабочего каталога.

Официальный [релиз rust-analyzer 2026-10-12](https://github.com/rust-lang/rust-analyzer/releases/tag/2026-10-12) предоставил `rust-analyzer 0.3.3081-standalone`. Windows ZIP совпал с SHA-256, опубликованным release API: `77f7a907f0e6f179281bac38e2d08435c974db9a5b99de52c5c963aff52883ec`. Глобальная установка language server не выполнялась.

Serena home, метаданные проекта, окружение и логи оставались в `work/workflow-efficiency-20261017/`. Пилот работал по настоящему MCP stdio через временный Python-клиент; это не подтверждает нативную интеграцию в уже запущенном разговоре Codex. GUI и dashboard отключены. Проект работал в режиме чтения; фактический список MCP-инструментов проверен: только `get_symbols_overview`, `find_symbol` и `find_referencing_symbols`. Ограничение только на уровне проекта сначала оставляло описания других инструментов; allowlist в изолированной общей конфигурации Serena сократил наружный набор до трёх.

Рабочая Rust-конфигурация включала явный исполняемый файл language server, существующий проектный `CARGO_HOME=.work/cargo-home`, офлайн Cargo, `linkedProjects: [E:/ModuleEngine/Cargo.toml]` и `cargo.autoreload: true`. `checkOnSave`, Cargo build scripts и proc macros оставались выключенными; число потоков ограничено. Запускались Cargo metadata и процессы выяснения параметров компилятора. Приёмка движка не запускалась, кэши не очищались.

Начальная конфигурация возвращала определения, но пустые ссылки, даже для положительных контролей. Один только переход на проектный cache не исправил результат. Затем явный `linkedProjects` и `cargo.autoreload` изменены вместе: отдельное причинное влияние каждого параметра не установлено. В этой конфигурации контроли вернули две ссылки `same_path` и три ссылки `load_workflow`. Финальная LSP-трасса сообщила `health: ok`, `quiescent: true`, без сообщения об ошибке.

Независимый reviewer сравнил все девять со свежими буквальными совпадениями: файлы и строки совпали после преобразования нулевой нумерации Serena в обычную нумерацию исходников от единицы. Это подтверждает эти рукописные ссылки на данном снимке; отключённая поддержка генерируемого кода по-прежнему ограничивает полноту.

## Замеры извлечения и решение

Оба подхода получили известные пути файлов. Таблица учитывает каждый MCP `content[].text` один раз и сравнивает его с stdout `rg`; дублированный structured result и JSON-оболочка исключены. Это успешные выбранные извлечения из разных сессий, а не единый полный прогон. Диапазоны `rg` уточнялись после первых чтений, поэтому эксперимент неслепой.

| Задача | Символы результата Serena | Символы уточнённого `rg` |
| --- | ---: | ---: |
| Полная общая структура `GameHost` | 1 339 | 1 265 |
| Сигнатура `GameWorker::spawn` и девять вызовов | 3 232 | 3 980 |
| Полный обработчик диалога Save As | 4 787 | 4 918 |
| Всего выбранные извлечения | 9 358 | 10 163 |

Четыре уточнённые команды `rg` заняли около 0,106 секунды времени subprocess без планирования и накладных расходов инструментов. Один успешный MCP-прогон занял примерно 3,25 секунды инициализации, 8,51 секунды первого запроса определения и 5,19 секунды поиска ссылок; диагностическая трассировка была включена. Ранее прогретый запрос определения занял 0,096 секунды. Это отдельные наблюдения, а не устойчивые оценки задержки или сравнение полного времени работы. При обнаружении инструментов MCP их описания добавили 7263 сериализованных символа; фактическая обработка нативным клиентом не измерялась.

Для дополнительного изучения принятия Save As чтение целых символов дало 7538 текстовых символов, два точных фрагмента `rg` — 1064. Инструменты символов не минимизируют контекст автоматически: целый метод нужен только тогда, когда этого требует вопрос. Ни один маршрут навигации не исполнял сохранение и не доказывал корректность транзакции.

**Решение:** избирательное применение семантической навигации обосновано, особенно для определения вызывающих функций и обзоров символов. Ограниченные `rg`/чтения исходников остаются подходящими для литералов и небольших известных участков. Оснований регистрировать Serena как постоянно включённый проектный MCP-сервис по этому пилоту нет: есть стоимость настройки/запуска и нет доказанного преимущества по общему времени или расходам аккаунта. Неоднозначные имена, алиасы, генерируемый код, более крупная незнакомая фича и окупаемость долгой сессии не проверялись. При последующей интеграции следует сохранить рабочую конфигурацию workspace, узкий набор инструментов, положительные контроли и запасной маршрут; одного успешного старта или пустого ответа недостаточно.
