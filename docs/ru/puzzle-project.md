# Игра-головоломка с ящиком

[English](../puzzle-project.md) | [Русский](puzzle-project.md) | [Документация](README.md)

`module-engine-project-puzzle` — небольшая авторская игра на основе `GameProject::empty()`. Она зависит от нейтральных контрактов движка и опционально от egui для управления и HUD. Зависимостей от пакета ARPG или проекта Two Arenas нет.

Проект предоставляет две схемы компонентов, две системы в расписании и расширение представления. Редактор устанавливает этот исходный пакет через общий каталог композиции. Обычные Hierarchy, Inspector, Scene, сохранение проекта и runtime используют эти регистрации; их панели не содержат специальных редакторов полей головоломки.

## Создание и игра

Из полного соответствующего пакета Full source:

```powershell
target/debug/module-engine-editor.exe --new-puzzle puzzle-project.json
target/debug/module-engine-editor.exe puzzle-project.json
```

На поле есть одна фишка, один ящик, стены и зелёная цель. Стрелки или WASD выполняют одно перемещение на новое нажатие клавиши. При движении в ящик он толкается, если следующая клетка свободна. Стены блокируют движение без расходования хода. Передвиньте ящик на цель за восемь ходов. Решённая игра или исчерпанный лимит ходов останавливает дальнейшие перемещения. Нажмите R или кнопку Restart на HUD, чтобы восстановить авторское поле и очистить счётчик ходов и результат модуля.

Решение поставляемого поля: **север, восток, юг, восток, север**. Игра выдаёт именованные события `puzzle.blocked`, `puzzle.moved`, `puzzle.solved` и `puzzle.failed` через общий контракт событий движка.

## Редактирование авторских данных

Выберите объект 1 в сцене `board`. Его компонент `puzzle.board` изначально равен `{}`; зарегистрированная схема разрешает следующие значения по умолчанию:

| Поле | По умолчанию | Ограничение |
| --- | --- | --- |
| `width` | 5 | Целое число, 3–64 |
| `height` | 5 | Целое число, 3–64 |
| `cell_size` | 1 | Число, 0.1–10 |
| `max_turns` | 8 | Целое число, 1–1024 |

Используйте числовые поля Inspector и **Apply fields**. Изменение `cell_size` меняет runtime-проекцию сетки, не меняя логического решения. У остальных объектов есть поля `puzzle.cell`: `x`, `z` и `kind` (`wall`, `goal`, `pawn` или `crate`). Проверка, принадлежащая исходному пакету, контролирует целочисленность координат, границы, корневое владение объектами, уникальность занятых клеток и обязательный состав board/pawn/crate/goal. Тот же защитный механизм пакета отклоняет недопустимые итоговые миры до публикации тика, прямого пакета команд или объединённого перехода сцены. Поздняя исходная система не может обойти эту проверку. При увеличении числа ходов переполнение отклоняется; восстановленные счётчики кадра должны соответствовать авторскому лимиту ходов.

Координаты сетки и размер клетки определяют начальные позиции при инициализации исходных систем первым тиком Play. Scene в режиме редактирования по-прежнему показывает авторские Transform и поддерживает обычные манипуляторы; отдельного редактора сетки нет. Одно лишь перемещение авторского Transform клетки не меняет её логику сетки, а инициализация Play проецирует клетку из координат `puzzle.cell`.

Авторское расписание выполняет `puzzle.turn` перед `puzzle.result`. Объявленная им активность компонентов содержит `puzzle.board` и `puzzle.cell`; renderer также предоставляет нейтральные схемы mesh/material. Health, AI, combat, данные кадра ARPG и авторские аудиосигналы отсутствуют. Состояние головоломки находится в `puzzle.frame/1` в общей карте данных модулей.

Сохраняйте и повторно открывайте проект обычными командами. Проект может хранить ресурсы отдельно от выбранного пакета Engine; стандартная привязка Save As сохраняет эту связь.

## Воспроизведение доказательств редактирования и runtime

```powershell
target/debug/module-engine-editor.exe --puzzle-check puzzle-project.json outputs/puzzle-check
```

Эта команда использует указанный файл, чтобы найти его проверенный контекст Engine и ресурсов, создаёт свежий preset головоломки в отдельной папке случая и оставляет указанный файл неизменным. Выполняются следующие проверки:

- Отрисовка настоящего общего Inspector, перетаскивание `puzzle.board.cell_size`, нажатие его настоящей кнопки **Apply fields** и проверка сохранности остальных значений схемы по умолчанию. Просмотр полей не должен создавать runtime host.
- Использование публичных функций Save As, Save и чтения для повторного открытия изменённого проекта с сохранением авторских значений и выбранной привязки Engine.
- Запуск настоящих сессий `GameHost` с мирами Objects и ECS, проверка заблокированного движения, решения за пять ходов, проигрыша по лимиту, игнорирования движений после остановки и перезапуска после обоих исходов. Правка Inspector должна влиять на инициализированный мир.
- Запись настоящих Vulkan-кадров 960×540 для начального, решённого и перезапущенного поля. Обе реализации мира должны давать равные логические решённые состояния и RGBA; Restart должен восстанавливать исходный кадр.
- Использование существующего Full-экспортера проекта, повторное открытие результата как редактируемого исходного пакета, затем запуск и рендер с экспортированной папкой, явно переданной как корень ресурсов и Engine.
- Проверка хеша исходного файла и байтов сохранённого авторского файла после исполнения.

Случай содержит PNG, снимки решённого состояния, сохранённый авторский проект, Full export и `puzzle-report.json`. В выходную папку также помещается последний отчёт. Адресный unit-тест редактора `puzzle_verification::tests::generic_inspector_save_reopen_and_puzzle_only_runtime_preserve_authored_project` покрывает настоящий процесс Inspector/save/reopen, а затем решает и перезапускает игру с реестром, устанавливающим только нейтральные встроенные модули и пакет Puzzle.

Это доказывает путь экспорта редактируемых исходников Full. Такой экспорт включает полное дерево исходников Engine и может содержать другие установленные модули и неиспользуемые ресурсы. Он не подтверждает минимальный самостоятельный пакет Player или физическое отсутствие исходников ARPG. Пустые авторские аудиосигналы проверяются; выделение аудиосервиса и отсутствие вызовов аудиовыхода находятся вне этого доказательства.
