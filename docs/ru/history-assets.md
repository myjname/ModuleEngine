# История, объединение и ресурсы

[English](../history-assets.md) | [Русский](history-assets.md) | [Документация](README.md)

## Undo/redo и контрольные версии

Вкладка «История» работает со снимками GraphDocument: графом, Rust/HLSL, параметрами, раскладкой, манифестами и авторскими game-сценами/шаблонами/исполнением. «Отменить»/«Повторить» и Ctrl+Z/Ctrl+Y возвращают документ. В редакторе хранится до 200 изменений; новая правка после undo отбрасывает redo-ветвь. Незавершённый File JSON нужно применить или отменить сначала. Локальный ExecutionGraph черновик не является сохранённой историей до успешного Apply.

История в памяти относится к текущему открытому документу и сбрасывается при открытии другого файла. «Сохранить контрольную версию» записывает полный снимок в .history рядом с JSON проекта. Имя записи уникально; существующая версия не перезаписывается. «Восстановить» возвращает документ и само становится отменяемым изменением.

Операции окна Assets, включая импорт, создание папки, переименование, перенос, удаление и восстановление файла, имеют собственную границу истории даже без изменения JSON. Undo/Redo восстанавливают файлы и документ вместе, проверяя их текущее содержимое перед откатом; результат сохраняется. Если файл был изменён сторонним инструментом после операции, редактор отказывается перезаписать его через историю. Завершённый жест Move/Rotate/Scale тоже создаёт одну запись; Escape отменяет незавершённый жест.

Checkpoint или merge содержат документ, но не полный исторический снимок всех файлов. Перед применением проверяются пути, ID, хеши и зависимости ресурсов. Версия с отсутствующим файлом, старым путём после переноса или удалённым ID отклоняется до изменения документа и истории. Нужные файлы сначала возвращают через файловый Undo либо корзину Assets. Исходники Rust/HLSL не переписываются автоматически при восстановлении версии. Подробнее — [Scene и Assets](scene-assets.md) и [API файловых транзакций](asset-workspace-api.md).

Время, живое состояние объектов, GPU-ресурсы, owned Custom runtime state и worker globals не записываются. Возврат авторского документа не является перемоткой Play. Legacy совместимые правки могут сохранить существующий мир; смена его контракта создаёт новый. Изменение авторской игровой сцены или общего ExecutionGraph требует Stop; совместимый hot apply Rust/HLSL имеет отдельный контракт сохранения живого состояния.

## Diff и трёхсторонний merge

Во вкладке «История» укажите общую исходную версию (base) и изменённый JSON другой ветви (theirs); текущий документ — ours. «Сравнить с текущим проектом» показывает категории и пути изменений. «Подготовить объединение» строит MergeResult, не записывая исходные файлы.

Обычные Graph nodes сопоставляются по ID в своей области; edges — по целевому узлу/входу. Поэтому два разных переподключения одного входа дают конфликт, а изменение разных узлов может объединиться. Вложенные Graph обрабатываются тем же способом. Для game.scenes[*].objects, ExecutionGraph stages/nodes и других обычных массивов поэлементного ID-aware merge пока нет: независимые правки одного массива в обеих ветвях дают конфликт массива целиком с base/ours/theirs. Разные поля/maps сцены или шаблона могут объединиться обычным объектным merge. Непересекающиеся строки Rust/HLSL объединяются; пересекающиеся сохраняются как source conflict. Это не доказательство корректности программы или сцены.

Каждый конфликт хранит path, base, ours и theirs. Предварительный документ сохраняет базовое значение; у конфликтующих новых узлов оно отсутствует. Обе новые версии сохраняются целиком в конфликтном отчёте. Выберите «Оставить текущую», «Взять другую» или «Вернуть базу». Только после разрешения всех конфликтов доступно применение результата; далее обычная проверка графа и компиляция проверяют его исполнимость.

«Сохранить результат вместе с конфликтами» создаёт новый merge-*.json с документом и конфликтами. Это отчёт MergeResult, а не обычный GraphDocument: не открывайте его как проект. UI пока не загружает отчёт обратно; библиотека имеет serde-представление и resolve для инструмента продолжения merge. Оригинальные файлы остаются доступны.

Библиотечные функции: diff_documents, merge_documents, MergeResult::resolve и ConflictChoice::Custom для собственного значения. Duplicate ID отклоняется, чтобы нормализация не теряла узлы. После merge порядок массива nodes может измениться; смысл связей задаётся ID. Live coediting, блокировки, серверная синхронизация и автоматический merge ресурсов не реализованы.

## Ресурсы

AssetId — стабильный строковый ключ манифеста. Путь относителен к каталогу проекта, SHA-256 фиксирует содержимое, dependencies содержит ID других зарегистрированных ресурсов. asset_manifest:null означает пустой манифест. Структура:

~~~json
{
  "schema_version": 1,
  "assets": {
    "mesh.main": {
      "path": "resources/model.bin",
      "sha256": "<64 hexadecimal characters>",
      "dependencies": []
    }
  }
}
~~~

Здесь hash — заполнитель, который нужно заменить хешем реального файла. API AssetManifest::register вычисляет его из файла; verify проверяет байты и ссылки на зависимости. Окно Assets индексирует проектные файлы, назначает недостающие ID и позволяет управлять ресурсами; новые назначения используют `asset://ID`, а старые относительные пути остаются совместимыми. Полный манифест также редактируется JSON или через исходный API. Экспорт дополнительно собирает транзитивные ресурсы игровых сцен.

Абсолютные/drive пути и выход выше корня отклоняются. Каноническое разрешение запрещает symlink, ведущий за пределы проекта. Разрешены относительные .. внутри корня. Export не подменяет существующий файл другим содержимым; изменение ресурса после регистрации требует явного обновления его hash.

## Что сохраняет экспорт

Полный исходный пакет содержит crates, docs, examples, assets, scripts, tools/dxc с DLL и лицензиями, Cargo.toml/Cargo.lock, toolchain-manifest.json, .gitignore и текущий project.json. .work и target не копируются. Зарегистрированные внешние ресурсы копируются в те же относительные пути. HLSL include-зависимости собираются рекурсивно и добавляются в экспортный asset_manifest с ID, относительным путём и SHA-256; исходный manifest не изменяется. Один относительный путь с разными байтами даёт ошибку. Циклы конечны, макросы include отклоняются.

Scoped exporter принимает asset_root и package_root отдельно: registered resources относительны к JSON, native sources/inline HLSL — выбранному Full пакету. Include roots: package/assets/gpu, затем package root; nested quoted include первым ищет каталог содержащего файла, angle — только include roots. Самостоятельный JSON без package marker не меняет compiler context. Source ID не считается именем файла.

Team export сохраняет готовую сборку, разрешённый gameplay и .sdk Core, удаляя inactive archive/неиспользуемые авторские фрагменты. Backend pins фиксируют Engine HLSL/include и DXC, оставляя обычные game assets вне immutable backend inventory. [Поставки](distribution.md) объясняют source manifest, profiles и SDK.
Экспорт требует новую или пустую папку вне всех копируемых деревьев: crates/docs/examples/assets/scripts/tools/.sdk/.user/.tools. Неполный результат при ошибке остаётся для диагностики; повторная попытка требует новой или явно очищенной пользователем папки. Исходные файлы не удаляются.

Сохранение существующего JSON создаёт уникальную .backup-* копию исходных байтов; загрузка schema 1/2 мигрирует только в памяти. Отсутствующие module_versions заполняются версиями установленного реестра при записи/экспорте. Конфликтующий pin сохраняется и даёт диагностику совместимости; exporter не исправляет его выбором другой версии.

## Инструменты и восстановление

toolchain-manifest.json фиксирует Windows x86_64 MSVC, Rust 1.99.0, rustup 1.29.1 и DXC release v1.9.2609 / executable 1.9.2609.5. Cargo.lock фиксирует Rust-зависимости, в том числе worker. Хеш rustup-init из [официального release checksum](https://static.rust-lang.org/rustup/archive/1.29.1/x86_64-pc-windows-msvc/rustup-init.exe.sha256), а также хеши DXC archive и компонентов закреплены в манифесте. Restore проверяет загруженные байты перед запуском/распаковкой.

~~~powershell
.\scripts\bootstrap.ps1 -Json
.\scripts\bootstrap.ps1 -Restore
~~~

Первый вызов — doctor: проверяет версии, хеши DXC и наличие Vulkan loader, не скачивает и не устанавливает. Отсутствующий инструмент даёт JSON с ok:false и exit 1. Второй вызов явно восстанавливает pinned Rust/DXC в локальные .tools/tools проекта и выполняет cargo fetch --locked для корневого Cargo.toml или Team .sdk/Cargo.toml с кешем .work/cargo-home. Rust Restore включает rustfmt/clippy; локальные cargo/rustc shims выбирают закреплённый toolchain. Если создан локальный Rust, подключите . .\.tools\env.ps1 в новой PowerShell-сессии.

MSVC build tools/Windows SDK и GPU driver являются требованиями хоста. Script не устанавливает их и не доказывает работоспособность адаптера по наличию vulkan-1.dll; это проверяется GPU self-check. Полный offline SDK отсутствует. В 0.3 после первоначального sandbox DNS отказа разрешённый повтор Restore скачал 13 pinned зависимостей в новый Team-кеш; последующие SDK compile/render прошли без внешнего CARGO_HOME/CARGO_TARGET_DIR. Эта проверка использовала наличные Rust/MSVC/драйвер. Doctor проверен с наличными инструментами и отсутствующим DXC; холодная установка Rust/MSVC/драйвера не подтверждена этой проверкой. Отдельный готовый Player не восстанавливает инструменты и запускает заранее собранные shaders/workers.
