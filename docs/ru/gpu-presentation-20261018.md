# Показ кадров на GPU: результаты проверок и ограничения

[English](../gpu-presentation-20261018.md) | [Русский](gpu-presentation-20261018.md)

Исторический снимок GPU-этапа: исходные обычные source15 и cold-выводы ниже сохраняют свой объём. Последующее [продолжение P0](p0-continuation-20261018.md) фиксирует первую допустимую cold PASS-попытку на восстановленной обычной сборке, текущие Windows/Linux сценарии, ограниченные window/authoring и synthetic fault доказательства. Прежние неудачи остаются неудачами; причина старых cold-таймаутов неизвестна.

**Обычные нативные требования пройдены на source15; холодный запуск ≤45 с остаётся открытым, привязка итоговых исходников и независимое заключение записываются во внешних записях ниже.** При обычном показе пиксели остаются на GPU. Текущие Windows-проверки изображений/времени жизни, экспорт/перемещение выбранного Player и все 12 процессов обычного A/B проходят неизменённые критерии. Это ограниченные измерения конкретных исходников, а не универсальное улучшение или статистическое доказательство отсутствия ухудшения. Прежний провал p95 source11 и все неудачные холодные/завершающие запуски сохранены. Сопоставимые старая/новая версии не успевают подготовить Game после итогового Stop, завершив обе измеряемые фазы; причина не приписана именно передаче через GPU.

## Реализованный контракт

Core `Frame` содержит либо полный массив CPU-пикселей `rgba`, либо непрозрачную ссылку `Arc<dyn GpuFrame>` с пустым `rgba`. Core/Host не интерпретируют графические дескрипторы. Приложение явно передаёт `PresentationTarget`; при занятом ограниченном пуле `render_presented` возвращает `None`, сохраняя последнее изображение, идентичность, время завершения, происхождение кадра, камеру для прицеливания и ожидающие одноразовые команды. Отклонённая цель вывода или кандидат сохраняют принятое состояние. Ошибка взаимодействия графических API сообщает диагностику без молчаливого перехода к передаче через CPU или включения отсутствующего необязательного модуля Vulkan.

Отдельный производитель кадров Vulkan разделяет ресурсы D3D12 с Windows WGPU/DX12. На Linux отдельные устройства Vulkan используют выделенную память OPAQUE_FD с точным совпадением UUID устройства и драйвера. Интерфейс копирует изображение и выполняет умножение цвета на альфа-канал на GPU в собственную текстуру `Rgba8Unorm`, сохраняя точное округление байтов egui без декодирования sRGB. Четыре арендуемых выходных слота ограничивают незавершённые кадры. Повторное использование разрешается фактическим завершением GPU-работы потребителя; удаление ссылки CPU, скрытая панель или пропущенный вывод в поверхность окна не означают завершения. При выходе сначала останавливаются производители, затем ожидаются зарегистрированные задачи освобождения GPU-ресурсов и лишь потом выполняется окончательное уничтожение.

Прежнее синхронное ожидание завершения GPU-работы производителем сохраняется. Новый игровой swapchain и общий асинхронный конвейер нескольких кадров не добавлены. Явный CPU/software-рендер, диагностический Glow, CLI/PNG-захват и чтение изображений для сравнения поддерживаются. При фатальном отказе отправки команды освобождения владения на Linux затронутые аренда и устройство удерживаются до выхода процесса; обычные успешные проверки не подтверждают этот исключительный путь.

## Пиксели, время жизни ресурсов и настоящий интерфейс

[Windows fixture06](../../outputs/gpu-direct-20261018/windows-gpu-fixture-06/result.json) и [Linux fixture02](../../outputs/gpu-direct-20261018/linux-gpu-fixture-02/result.json) проходят по **21 сценарию, включая 16 сравнений без различающихся байтов и ошибок каналов**. Forward/Deferred покрывают 1920×1080 и невыровненный размер 1919×1079. Другие сценарии покрывают отключение/удаление AO/AA, альфа-канал собственного завершающего прохода, изменение размера, сохранение после отклонённого шейдера/цели вывода, замену графа, пересоздание рендера подобно Stop, ограничение четырёх аренд и уничтожение производителя/панели. Новый сценарий удерживает последний кадр после уничтожения владельцев интерфейса и безопасно освобождает его. Каждая проверка записывает `registered_jobs=1`, `joined_jobs=1`, `completed_copies=1`, `unconfirmed_copies=0`, `failed_jobs=0`.

При обычном выводе число прочитанных и загруженных через CPU байтов равно нулю. Чтение для сравнения явно диагностическое: по 33 611 092 байта, это не запасной путь обычного показа. Проверки неизменности исходников, защищённых данных, зависимостей и исполняемого файла после запуска проходят. Windows использует RTX 4080 SUPER/DX12, Linux — Ubuntu/WSL llvmpipe Vulkan. Linux остаётся привязан к source11, а не к проверке расписания source15. Обе проверки внеэкранные: без поверхности окна, отрисовки eframe, vsync или композитора. Они не подтверждают аппаратный Linux, произвольные драйверы/ABI, физический вывод на монитор или равенство изображений разных платформ.

[Три оконные проверки завершения](../../outputs/gpu-direct-20261018/shutdown-probe-02/result.json) заканчиваются exit 0, каждая со 120 различными кадрами GPU, без передачи пикселей через CPU и ошибок кадров. Они используют сохранённый совместимый Full03 и подтверждают исправление завершения работы, но сами по себе не производительность текущей поставки. [Текущие тесты Host](../../outputs/gpu-direct-20261018/scoped-tests-05-host/result.json) проходят: 64 обычных, один ignored, включая семь детерминированных тестов правил фазы без повторного подсчёта; прежние проверки viewport/endpoint сохраняют отдельные привязки к исходникам. Release-проверка только UI содержит в CargoJSON Player features `["ui"]` и не содержит артефакта игрового `module-engine-vulkan` (33.76 с): это разделение компиляции, а не проверка исполнения.

[Прогретый интерфейс Editor](../../outputs/gpu-direct-20261018/warm-editor-probe-01/launch.json) проходит за 33.2727902 с внутреннего времени: настоящие панели Graph/Scene/Game, по 30 прогревочных и 90 измеряемых вызовов окна в фазах Stop/Playing, 90+90 изменений сдвига графа, продвижение симуляции и Play/Stop через диспетчер команд с новым исполнителем при нулевом времени. Две задачи освобождения GPU зарегистрированы, дождались завершения и закончили копирование; неподтверждённых и неудачных задач нет. Вставленные программно движения указателя не являются ручной проверкой окна на переднем плане. Прогретые зависимости не доказывают холодный запуск; наличие текстуры не означает новый отрисованный кадр на каждый вызов окна.

## Диагностика и ещё предварительное изменение расписания

[Трассировка source12](../../outputs/gpu-direct-20261018/timing-trace-01/result.json), диагностический снимок `4a6cdc9b…`, ограничивает доступность зафиксированного кадра примерно **3.4458 мс между трассируемыми чтениями интерфейса, допускающими постановку изображения на вывод**: уже наступившая отрисовка задержана предшествующим шагом, опубликована и заменена до следующего чтения. Это показывает наблюдавшийся механизм расписания/захвата, а не задержку физического вывода или одинаковую причину каждого пропущенного кадра.
