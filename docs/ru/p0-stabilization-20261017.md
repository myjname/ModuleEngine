## Изменения и причины

| Область | Подтверждённая проблема и полученное поведение |
|---|---|
| Запуск Windows Player | Завершаемая до GUI подготовка Windows отделяет MTA-инициализацию поиска MSVC от STA/OLE-потока winit и предотвращает наблюдавшийся `RPC_E_CHANGED_MODE`. Открываются обычные окна Editor-Player и собственного перемещённого standalone. |
| Linux migration | Сравнение без учёта регистра ошибочно отклоняло разные `project.json` и `PROJECT.json`. Non-Windows сравнивает нормализованные пути точно; Windows сохраняет прежнее сведение регистра. Настоящие aliases и занятые назначения отклоняются. Реальный Puzzle regression сохраняет исходные/unknown/null/binding/resource-данные. |
| Debug proof hashing | Неоптимизированный SHA-256 превышал неизменённый 30-секундный срок подготовки Scene. Только development `sha2` получает opt-level 3; Debug assertions, release-настройки и точные cache/SDK pins сохранены. На записанном snapshot исправления неизменённый случай сменил failure 30.29 с на pass 22.50 с. |
| Общее представление | Консервативная raw SRT-интерполяция выполняется до обогащения Content. Границы lifetime/hierarchy/reset/неподдерживаемых providers переключаются без смешивания; смена identity follow-camera тоже. Кадр, фактическая камера, source-pair/alpha/origin, успешная identity и реальное время завершения публикуются вместе; failure/None сохраняет прежний набор. |
| Планирование и владение пробуждением | Прерываемые Windows high-resolution waits сохраняют armed timer при преждевременных coarse timeouts, с ограниченным монотонным watchdog и блокирующим повтором. Исходный Linux race failure сохранён; текущие Windows Host 53 ordinary passes/1 ignored и Linux Host 49/1 дают green-покрытие, включая ownership regression. |

## Уточнение контрактов и границы

Ожидающие **Custom-emitted** clear/copy operations образуют упорядоченные one-shot batches, сохраняются при render failure и потребляются только после успешной submission. Их удаление не создаёт одинаковый лишний кадр; отказ при переполнении транзакционен и ограничен; headless stepping отбрасывает render-only batches без GPU effects. Постоянные authored **ReadyVariant project recipes** — существующие selected controls, заново создаваемые `effective_render_controls`/`project_commands` при каждом реальном render, включая допустимые intermediate poses. Ревью не установило противоположного production-контракта. Согласованный Host EN/RU-контракт уже описывает это различие; независимое ревью охватывает и эту документацию. Это не утверждение, что любая authored resource command выполняется один раз.

Парные workflow-документы теперь указывают фиксированную симуляцию 60 Гц и целевое планирование presentation 120 Гц с eligibility/static suppression, без гарантии измеренных 120 FPS.

Hardware Linux, произвольная ABI/driver portability, native Linux WAV/dialog gaps, физическая display latency и sandboxing недоверенного Rust остаются документированными platform/product limits. Будущие animation/PBR/navmesh/network/mobile systems — отдельная работа по плану развития. Все 33 protected files и исходные пользовательские данные сохранены. Ранние 84d/e465/6bc4 passes и failed candidates сохраняют точную source scope; финальные правки документации не переименовывают runtime builds. [Независимый итоговый decision record](../../outputs/reviews/p0-final-20261017/review.md) связывает итоговый снимок исходников и документации отдельно от неизменённых native inputs. **Документированные проверки P0 и независимое ревью завершены; указанные выше границы сохраняются.**
