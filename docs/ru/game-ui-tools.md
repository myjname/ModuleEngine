# Игровые элементы управления и авторские инструменты модулей

[English](../game-ui-tools.md) | [Русский](game-ui-tools.md) | [Документация](../README.md)

Установленная исходная композиция выбирает игровое представление по ID вклада.
Player и Editor используют одинаковые callback-функции `UiContribution`; в
диспетчеризации нет названий действий конкретной игры. Отсутствующий вклад не
добавляет игровое управление. Общий перезапуск с клавиатуры доступен и без
установленного игрового представления. Установленный callback ввода владеет
назначениями клавиш, включая смысл R; именованное действие перезапуска уровня
не означает перезапуск хоста.

## Игровой ввод из элементов управления

Если задан `UiContribution.controls`, он заменяет прежний callback `hud` и
возвращает `GameInput`: нажатые `actions`, текущие `values`, контекст конкретного
нажатия `action_values` и перезапуск сессии `restart`. `draw_controls_for`
возвращает этот пакет. Если более полный callback управления не установлен, прежний boolean HUD
адаптируется в `restart`. `draw_hud_for` остаётся совместимой точкой входа только
для перезапуска; для игровых действий требуется `draw_controls_for`.

## Состояние приложения и право закрытия

Установленный `UiContribution.controls_with_status` имеет приоритет. Он получает
Core `GameUiStatus` вместе с тем же неизменяемым состоянием игры и аргументами
представления и возвращает Core `GameUiResponse`. Состояние содержит
`can_close_application`, текущую диагностику `services` и текущие ошибки хоста
`errors`. Это контекст приложения, отделённый от авторских данных, состояния
игровых правил и протокола Custom. Диагностика сервисов показывает текущее
состояние восстановления/ошибки; исторические сбои Activity не превращаются
в навсегда закреплённые ошибки игрового UI.

`GameUiResponse.input` несёт обычный `GameInput`, а `close_application` — отдельный
запрос приложения. Нативный Player предоставляет право закрытия и обрабатывает
разрешённый запрос обычной командой закрытия окна. Editor передаёт
`can_close_application:false` и отклоняет игровые запросы закрытия. Приложение
проверяет право, даже если исходный callback запрашивает закрытие без разрешения.
Принятое закрытие подавляет игровой ввод того же жеста до отправки. Закрытие
не представлено именем игрового действия или дополнительным полем протокола
`GameInput`.

Интерактивные пути используют `collect_input_with_status_for`; совместимый
`collect_input_for` предоставляет состояние по умолчанию без права закрытия.
Прежние callback-функции `controls -> GameInput` и boolean HUD поддерживаются.
Представление с доступом к состоянию приложения владеет трактовкой его сочетаний
клавиш: Escape может ставить игру на паузу вместо закрытия окна. Представления
с прежними callback-функциями сохраняют существующее поведение Player,
закрывающее окно по Escape. Исходные назначения R и резервный R при отсутствии
вклада остаются прежними.

Приложения используют `collect_input_for`, чтобы нарисовать элементы управления
до сбора мирового ввода и объединить два пакета один раз. Исходный callback ввода
вызывается не более одного раза при каждом сборе; он может потреблять события
клавиш или хранить собственное состояние действий. Предпросмотр прицеливания
использует предыдущий принятый пакет, поэтому может отставать на один кадр UI,
не потребляя текущее действие. Значения элементов управления заменяют мировые
значения с теми же ключами; имена действий объединяются, а контекст нажатия из
элементов управления заменяет совпадающие ключи. Пакеты только со значениями
также считаются вводом, включая слайдеры без действия. Перезапуск отменяет все
игровые действия и значения того же кадра и имеет приоритет над старыми нажатиями
в очереди. Editor объединяет видимые панели до потребления ввода кадра; Player
отправляет ввод один раз за кадр UI. Очередь нажатий сохраняет захваченный контекст,
а удерживаемые значения остаются актуальными. Editor на паузе не отправляет
игровое управление.

Принадлежность указателя интерактивному виджету HUD не позволяет его жесту попасть
в мировой callback. Непустой пакет элементов управления во время жеста указателя
также подавляет мировой пакет. Удерживаемый мировой ввод может приостанавливаться,
пока этот жест принадлежит элементам управления. Callback должен возвращать
действия только при завершённом действии виджета, а текущие значения — пока
изменяется удерживаемый элемент управления. Само рисование HUD не должно
генерировать действия. Доступность необязательного пакета и активный ID
представления хоста определяют участие его callback-функций.

## Инструменты с неизменяемым исходным документом

`Editor::register_module_panel` сохраняет API callback для чтения.
`Editor::register_module_tool` регистрирует callback с теми же неизменяемыми
входами `GraphDocument` и `ModuleRegistry`. Результат имеет тип
`Result<Option<GraphDocument>, String>`: нет завершённого изменения, документ-кандидат
либо диагностика. Callback не получает внутренности Editor, изменяемый авторский
документ, историю, состояние Play, дескриптор публикации файлов или право сохранения.

Инструменты с работой в нескольких кадрах используют необязательный callback
`Editor::register_stateful_module_tool`. Он получает те же неизменяемые данные
и Core `ModuleToolContext { storage_id, document_instance, revision }`, возвращая
`Result<ModuleToolResponse, String>` с полями `candidate` и `dirty`. Прежняя
регистрация совместима с немедленными предложениями и инструментами для чтения;
она не сообщает приложению о закрытых локальных правках.

`storage_id` обозначает один зарегистрированный инструмент одного Editor
независимо от видимой панели. Храните под этим ID один кэш инструмента с текущими
document/revision внутри. Успешные Open, New, повторная загрузка или Save As в
другой файл принимают новый `document_instance`, даже при одинаковых игровых
данных. Save и Save As в тот же файл сохраняют экземпляр; отмена, ошибка чтения
или публикации сохраняют прежние экземпляр и черновик. Закрытие/повторное открытие
панели не отбрасывает работу. Эти ID временные и не входят в авторский JSON.

Сообщайте `dirty`, пока локальные правки не разрешены, включая некорректный
локальный черновик. Предложение подтверждается только после обычной проверки и
публикации Editor. Принятый Apply, включая no-op, и явный Discard увеличивают
только `revision` своего инструмента и очищают только его признак правок.
Отклонение предложения и ошибка callback сохраняют прежние pending-статус и
подтверждение. Исходный модуль обязан вернуть dirty-статус после редактирования;
ошибка callback не сообщает о новой закрытой работе. При изменении document/revision
перестройте кэш из текущего авторского документа. Это учитывает Apply с последующим
Undo до следующего рисования; публикация одинаковых данных другим инструментом
не подтверждает работу этого инструмента.

Неразрешённые stateful-инструменты участвуют в защите несохранённых правок.
Save/Save As, Check, экспорт и запуск Play требуют предварительного Apply или
Discard. Open/New/Close не могут обойти это через Don't save. Guard и отчёт
операции предлагают `Discard module draft` для каждого инструмента, даже если
владелец неактивен или панель закрыта; недоступный исходный callback для этого
не вызывается. Cancel возвращает в текущий проект. Другие модульные, JSON-,
Rust-черновики и черновики исполнения не очищаются. Защита предотвращает первый
игровой такт и его эффекты; прежние чтения при подготовке остановленного preview
не удаляются. Черновик не сохраняется этой системой при аварийном завершении.

Инструмент доступен только при установленном и активном модуле-владельце по
общему `CompositionContext::activity`, включая системы игрового расписания без
узла корневого графа или избыточного переключателя Engine.
`engine_only` дополнительно требует авторских прав Full с доступными подходящими
исходниками; Team не может получить это право через инструмент. Editor отклоняет
применение во время Play (включая сессию Play на паузе), при активных черновиках
документа/исполнения либо незавершённом жесте сцены. Кандидаты Project сохраняют
обычную политику Full/Team для проекта и проверку сцены, ресурсов и предпросмотра.
Инструмент `engine_only` использует явную проверку Engine для игровых и прежних
документов, может менять blueprint Full и устанавливает новую базовую политику
Project после успешной публикации. Он по-прежнему проходит те же проверки сцены,
ресурсов и предпросмотра. Инструмент Project не может получить права Engine
посредством кандидата.
Отклонённые и неизменённые кандидаты сохраняют исходный документ и историю.
Ошибка callback публикует только диагностику.

Каждый возвращённый кандидат означает один завершённый авторский жест. Editor
проверяет его до публикации и записывает одну границу Undo независимо от обычной
задержки объединения истории. Инструмент с перетаскиванием в течение нескольких
кадров использует описанный выше stateful-контракт и возвращает кандидата при
завершении жеста. Изменения сцены используют существующую границу публикации
Inspector. Только Editor владеет состоянием несохранённых изменений, Undo/Redo,
Save/Save As, проверками и публикацией файлов. Принятие кандидата меняет авторские
данные в памяти; файл при этом не сохраняется. Отмена и ошибки сохранения
сохраняют прежний транзакционный контракт.

Тесты синтетического вклада покрывают полные пакеты управления, boolean-адаптер,
обнаружение пакетов только со значениями, потребляющие исходные callback-функции,
исходные назначения R и изоляцию указателя HUD. Тесты Editor
проверяют изменение сцены исходным инструментом, один Undo, сохранность при
отсутствии изменений и ошибке, неактивного владельца и отказ Full/Team/Play.
Также проверен владелец из независимо запланированной исходной системы без узла
корневого графа или переключателя Engine. Это покрытие контрактов; оно не подтверждает нативное взаимодействие в активном
окне или приёмку конкретной игры.
