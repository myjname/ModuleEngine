# Сквозная приёмка игры и доказательства замеров

[English](../game-verification.md) | [Русский](game-verification.md) | [Документация](README.md)

Проверка игры использует тот же `GameHost`, что редактор и самостоятельный Player. Ей
требуется настоящее устройство Vulkan. Из полного исходного проекта:

```powershell
.\outputs\ModuleEngine.exe --game-check .\game-project.json .\outputs\game-verification
```

Для экспортированного runtime-пакета вызовите его `Player.exe` с `--game-check`,
`project.json` пакета и выходной папкой. Путь пакета выбирает запечатанные
shader artifacts и заранее собранные Rust workers; проверка не компилирует их.
Не размещайте выходную папку внутри запечатанного пакета: дополнительные файлы
являются доказательствами, а не поставляемыми зависимостями игры.

## Что доказывает проверка

1. Одна авторская сцена и 180 детерминированных кадров действий исполняются через настоящие
   хранилища Object и ECS. На каждом tick сравниваются сущности, снимки сцен, выданные события
   и состояние каждой системы, включая состояние compiled Custom. Настоящий вывод Vulkan
   с импортированным контентом должен совпадать пиксель в пиксель.
2. После всех шагов Custom размещается отказ native-валидации. Попытка
   tick должна восстановить объекты мира, состояния executor, принадлежащие экземплярам состояния worker и
   управление renderer. Замена этого валидатора принимающей реализацией
   должна позволить прежней игре продолжиться.
3. Игрок без участия человека использует действия движения и атаки, чтобы победить исходных
   20 врагов, войти в настоящий портал и победить босса. Тестовый автопилот обходит
   препятствия и отходит во время предупреждений. Он не телепортирует акторов,
   не удаляет врагов и не выдаёт runtime-команды урона. Его авторская fixture повышает
   здоровье игрока до 5000 для устойчивости; урон врагов, время атак и количество
   врагов остаются прежними. Это доказывает механику прохождения, а не игровой баланс.
4. Отдельная авторская fixture задаёт здоровье игрока 1. Настоящие атаки врагов должны
   выдать смерть игрока и поражение, а действие restart должно восстановить сцену.
5. Производительность использует переданный поставляемый документ без изменения здоровья fixture:
   30 прогретых кадров, затем 120 измеренных кадров в 1920×1080. Отчёт проверяет,
   что осталось не менее 20 живых врагов, а игрок всё ещё играет.

Unit tests Core независимо покрывают шаблоны и overrides, неверные ссылки,
типизированные зависимости ресурсов, откат внешнего commit, фильтрацию архива
неактивных компонентов, блокирование коллизиями, один удар на цель за взмах и ввод с фиксированным шагом.

## Интерпретация производительности

Замер охватывает вызов `GameHost`: симуляцию, Custom workers, потребление звука,
обогащение снимка импортированным контентом, настоящий Vulkan-рендеринг и GPU readback. Он исключает
v-sync, представление ОС/окна и отрисовку HUD редактора. Поэтому `mean_processing_fps` —
измерение скорости обработки, а не утверждение о частоте представленных кадров.

Отчёт включает среднее, median, p95 и максимальное время обработки, время симуляции и
рендера, кадры сверх бюджета, имя устройства, фактическое число врагов и исходные
120 временных отсчётов. `target_met` требует правильной нагрузки, среднего времени обработки
не выше 1000/60 миллисекунд и p95 не выше этого бюджета. Невыполненная
цель сохраняется как `false`; тест никогда не подменяет разрешение рендера меньшим
или не уменьшает число врагов, чтобы получить успешный результат.

## Файлы доказательств

| Файл | Назначение |
| --- | --- |
| `game-report.json` | Функциональные результаты, раскрытие fixtures и измеренное время |
| `game-parity-objects.png`, `game-parity-ecs.png` | Совпадающий вывод геометрии/контента Vulkan |
| `progression-fixture.json` | Точный независимо подготовленный авторский тестовый вход с высоким здоровьем |
| `game-start.png`, `game-boss-scene.png`, `game-victory-scene.png` | Доказательства рендера сцен по ходу прохождения |
| `boss-warning-state.json` | Настоящие данные подготовки атаки и предупреждения |
| `defeat-state.json` | Состояние смерти игрока, вызванное атаками врагов |
| `game-performance-1080p.png` | Отрендеренный вывод в измеряемом разрешении |

Отрендеренные PNG показывают вывод сцены `GameHost`. Они не включают HUD редактора/Player,
поэтому сами по себе не доказывают видимость полос здоровья или опасных областей. Проверка UI
и настоящий самостоятельный запуск предоставляют эти отдельные доказательства. Исходный проект
не меняется при проверке; fixtures и отчёты записываются только в
указанную выходную папку.
