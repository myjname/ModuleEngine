# Открытые вопросы после 0.4

[English](../questions.md) | [Русский](questions.md) | [Документация](README.md)

Принятые для 0.2/0.3/0.4 решения записаны в [decisions.md](decisions.md); объём игрового этапа — в [next-stage.md](next-stage.md). Сцены, статический контент, persistent Custom и Windows Player уже реализованы с описанными ограничениями. Этот список относится к дальнейшему развитию.

| Вопрос | Что изменит решение |
| --- | --- |
| Какие задачи следующими должны получить полноценное визуальное представление Rust: управляющий поток, функции/типы или работа с коллекциями? | Приоритет следующего подмножества и тестовые примеры. Пока неизвестные фрагменты остаются редактируемым текстом. |
| Как сопоставлять AST после неоднозначного перемещения, копирования и переименования кода? | Правила сохранения ручной раскладки и постоянных ID. Текущий перепарс может её сбросить. |
| Какой графический backend нужен после Vulkan и какие ограничения переносимого renderer API приемлемы? | Портируемость шейдеров, ресурсов и команд. |
| Когда нужны нативный swapchain и несколько одновременных отправок производителя сверх текущей одной ожидающей отправки/четырёх выходных аренд? | Профилирование полного кадра, бюджеты задержки/ресурсов и доказательства необходимости дальнейшего параллелизма. Обычный нативный показ уже не читает пиксели на CPU; явное диагностическое чтение остаётся отдельным. |
| Какие масштабы сцены и типы геометрии нужны для виртуализированной геометрии уровня Nanite-подобного подхода? | Буферные контракты GPU, загрузка мешей, culling/LOD и streaming. Текущий Custom manifest описывает изображения и Scene3D; произвольные buffer/geometry-порты и virtual geometry ещё не реализованы. |
| Какие temporal-ресурсы и motion vectors нужны для TAA/истории кадра? | Новые ресурсные контракты; текущий FXAA не хранит прошлый кадр. |
| Какие операции действительно нужны облегчённым ролям художника, автора игры и разработчика движка? | Уточнение отдельных будущих профилей художника/дизайнера. В 0.3 уже есть Full/Team с authoring boundary; полный source export сохранён. |
| Нужны ли сторонние динамические плагины, отдельно поставляемые бинарно? | Стабильный ABI, управление версиями и загрузчик. Сейчас расширения собираются из исходников. |
| Какие расширения контента нужны после статического glTF/GLB и PNG/JPEG? | Скелетная анимация, прозрачность, полный PBR и другие форматы. Первые статические модели/текстуры/материалы уже реализованы в 0.4. |
| Какие правила долговременного сохранения прогресса и версий состояния нужны? | Явное состояние Custom между кадрами и hot apply уже реализовано; запись игровых сохранений и долгосрочная миграция остаются отдельной задачей. |
| Нужно ли исполнять недоверенный сторонний Rust? | Отдельная реальная sandbox-модель; текущий worker имеет обычные права процесса. |
| Когда понадобится одновременное live-редактирование несколькими пользователями? | Сервер, авторство операций и стратегия конфликтов. Сейчас выбраны локальная история и merge файлов. |
| Как развить формат сцен дальше? | В 0.4 есть authored scene, стабильные ID/ссылки, шаблоны и overrides; дальше — версионирование расширенных компонентов, вложенные шаблоны и игровые сохранения. |
| Как поддерживать несколько установленных версий одного модуля и автоматические миграции? | Resolver нескольких версий и адаптеры сторонних модулей. Сейчас pin должен точно совпасть с установленной реализацией; известные форматы 1–3 поддерживают явную миграцию в копию с проверенным snapshot контрактов. |

Дополнительные технические ограничения текущей версии перечислены в custom-rust.md, gpu-hlsl.md и history-assets.md; они не считаются обещанными возможностями.
