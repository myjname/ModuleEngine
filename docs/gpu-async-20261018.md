## Behavior and boundaries

Native Vulkan now admits one `Pending(ticket)` submission and publishes it once through nonblocking exact-ticket polling. Four output leases and actual consumer GPU completion still bound reuse. `Busy` admits no work; `Ready(Frame)` supports immediate CPU/software output. Frozen scene/camera/size/revision/tick/provenance belong to the completed pixels; pending/error/repeated output cannot manufacture freshness. Admission consumes only the accepted one-shot command prefix, never replayed after a later GPU error.

Worker polls and publishes completed output before a potentially slow simulation step and again after an actual step attempt, including rollback. The existing one-shot observed-collision phase policy recognizes the same private flight identity crossing exactly one successful tick, frozen epoch/deadline and actual matching completion/headroom. A second step/reset/error/cancel/foreign flight cannot inherit the correction; an existing later deadline is preserved. Fixed 60 Hz simulation and 120 Hz presentation scheduling target remain unchanged. Native JSON does not expose the private phase key; deterministic actual-Actor fixtures establish its causal guards, not an inferred native trace.

Scene panes use process-local owner routing, ready mailboxes, deduplication and bounded FIFO demand; UI traversal retains cached visible panes and drops hidden/closed ownership without waiting. Displayed camera/revision/size govern projection and new hit/drop geometry; active gestures retain captured camera. F1 preserves completed output before a successor admission error.

Uploads, atlas images, command resources and pipelines/layouts stay alive until actual GPU completion. Cancellation abandons publication, not ownership; reaping may wait until next submit/backend destruction. Renderer Drop transfers unfinished work to an owned background job: only it may wait up to 30 s on its own fence. Shutdown reports nested producer registered/joined/completed/unconfirmed/failed counts alongside consumer retirement. Unknown failure/timeout/panic/thread-start error pins affected resources/device rather than reusing busy memory. Explicit CPU/software/Glow/PNG diagnostics retain synchronous readback and reject conflicting pending native work. No swapchain, multiple producer submissions, rate/cap change, gameplay/schema change, tool installation or authored-data replacement is included.
