# Авторские сцены и граф игровых систем

Откройте **File → New Project → Empty scene** или **Two arenas example**, выберите отдельную новую/пустую папку. Авторские окна — **Scene / Hierarchy / Inspector / Assets**; для Play откройте **Windows → Game**. Папка может находиться в `projects/` или `outputs/` установки движка, но не в копируемых ресурсах. Новый игровой проект использует текущую архитектуру Engine; при выборе **Не сохранять** для New используется её последняя сохранённая версия. Сохранение записывает `game` в файл графа; изменения игрового состояния при Play в этот файл не попадают. [Работа с Scene и Assets](scene-assets.md), [меню и сохранение](editor-workflow.md).

Save As переносит авторскую сцену, шаблоны, overrides, отключённые данные и всю библиотеку `assets/` вместе с объявленными зависимостями. При подтверждённой замене существующего файла назначения сохраняются резервные копии его метаданных; конфликтующий ресурс не заменяется. Отмена или ошибка открытия/создания другого проекта сохраняет текущую работу. **Check Project** и экспорт после **Не сохранять** используют версию на диске, а несохранённая сцена и черновики остаются в редакторе.

При первом запуске Project создаёт раскладку Scene / Hierarchy / Inspector / Assets. Старая личная раскладка переносится с сохранением разделителей и видов; прежние Project Viewport/Tree/Components становятся авторскими окнами, одиночный старый Game — новой стандартной раскладкой. Windows активирует открытую область нужного типа или добавляет её рядом с активной. Личная раскладка не является частью экспортируемой архитектуры. Пустая сцена использует существующую камеру предпросмотра и освещение renderer; отдельных авторских Camera/Light-компонентов этот шаблон не создаёт.

## Сцены и объекты

Список сцен в **Hierarchy** выбирает авторский предпросмотр. Поле **Scene name** и **+ Scene** создают пустую сцену; **Duplicate** копирует текущую со всеми объектами, локальными ID, ссылками и шаблонами. **Set as entry** назначает стартовую сцену Game и экспортированной игры. Выбранная авторская сцена и стартовая сцена могут различаться.

Выберите объект в Hierarchy или кликом по геометрии в Scene. **+ Object** создаёт объект с новым ненулевым ID. Манипуляторы Scene изменяют трансформацию; числовые position, rotation в радианах, scale, parent и цвет доступны в Inspector. **Delete** удаляет объект и его потомков; ссылки оставшихся объектов на удалённые ID очищаются. Цикл родителей или другое некорректное состояние отклоняется целиком. Игровые акторы остаются корневыми; иерархия поддерживает декоративные объекты.

**Play** запускает копию. WASD двигает игрока, ЛКМ атакует в сторону курсора, R перезапускает текущий игровой пример. **Pause** сохраняет runtime и приостанавливает его; **Play** продолжает. Авторские изменения и применение нового графа требуют **Stop** — пауза не заменяет остановку. После Stop возвращаются авторские позиции и объекты.

## Поля компонентов и шаблоны

Обычный инспектор показывает компоненты, объявленные активными `SystemDescriptor.components` или явным `SystemNode.params.components` для Custom, и mesh/material при подключённом renderer с контрактом `Scene3D → Frame3D`. Он также учитывает участие самого объекта: поля отсутствующего компонента не появляются как настройки объекта. **+ Component from active modules** создаёт черновик нужного компонента; заполните его и нажмите **Apply fields**.

Виджет определяется типом сохранённого поля: числа — drag controls, bool — checkbox, строки — текст, массивы — несколько полей. Это текущая автоматическая форма по JSON-данным; metadata систем пока перечисляет имена компонентов, а не полноценные enum/range/help-схемы каждого поля. Для нового native-компонента разработчик объявляет его имя в descriptor и записывает исходные поля компонента; они появляются той же формой без отдельного редактора.

Неактивные данные сохраняются в авторском проекте. Они скрыты из обычного инспектора и доступны в явном разделе **Advanced: raw components / overrides / references**. Здесь можно изменить maps целиком, добавить нестандартное поле или объектную ссылку. **Apply raw JSON** проверяет кандидата; неверный JSON или невалидная сцена не заменяют сохранённый источник.

**Create template from selected** создаёт связанный шаблон из текущих разрешённых полей и цвета объекта. Позиция, parent, ID и ссылки остаются у экземпляра. Поле имени необязательно: при пустом имени редактор выбирает свободное. Остальным объектам шаблон назначается в списке **No template / template name**.

Раздел **Linked template source** редактирует defaults; **Apply template defaults to instances** обновляет все связанные экземпляры. Индивидуальная правка у экземпляра записывается в `overrides`, например:

~~~json
{
  "prefab": "small-monster",
  "components": {},
  "overrides": {"health.maximum": 80.0},
  "references": {}
}
~~~

Поэтому новая максимальная жизнь шаблона действует на остальные экземпляры, а этот сохраняет 80. **Inherit defaults** удаляет overrides и локальные поля выбранного компонента, возвращая defaults шаблона. Переключение или снятие шаблона сохраняет явно заданные данные экземпляра; при снятии текущий разрешённый вид превращается в обычные компоненты объекта.

## Свои ресурсы

Откройте **Windows → Assets**. Проводник показывает папки и файлы, поддерживает поиск, фильтр, превью, импорт и управление файлами. Модель, перетащенная в Scene, создаёт новый объект. Текстура, перетащенная на геометрию объекта, назначает `material.base_color_texture`, сохраняя tint и остальные поля. Замена модели существующего объекта выполняется явно в Inspector.

**File → Import Asset…** либо **Import** в Assets открывает нативный выбор glTF/GLB, PNG/JPEG или WAV. Модели копируются вместе с зависимостями. Импорт не назначает ресурс автоматически: используйте перетаскивание или Inspector. После импорта обновляются индекс и превью. WAV предназначен для игровых audio cues и не является mesh/texture.

Импорт использует отдельную папку, чтобы не перезаписать существующие ресурсы. Новые назначения хранят `asset://ID`; старые относительные пути совместимы. **Refresh** перечитывает файлы и обновляет кеши. Переименование/перенос сохраняют ID и известные ссылки. Правила сохранения, удаления, Undo и корзины — в [scene-assets.md](scene-assets.md).

Пример данных:

~~~json
{
  "mesh": {"path": "assets/models/demo_crystal.glb"},
  "material": {"base_color": [0.8, 1.0, 1.0, 1.0], "base_color_texture": "assets/textures/stone.png"}
}
~~~

Фактические ограничения glTF, текстур и GPU-material ABI описаны в [content.md](content.md) и [gpu-hlsl.md](gpu-hlsl.md).

## Порядок систем и typed pins

Окно **Gameplay Systems** с заголовком Executable systems доступно автору Engine. **Stages, order and declared resources** содержит список стадий и узлов в точном порядке исполнения. **Earlier / Later** меняет порядок; перетаскивание узла на canvas меняет только его расположение на экране. Новые стадии, удаление стадий/узлов и типизированные ресурсы создаются здесь же. Palette добавляет реально установленный модуль в последнюю стадию.

`after` — отдельные явные ограничения по ID экземпляров. Перемещение их не стирает. Исправьте ограничения в JSON или явно нажмите **Replace after constraints with displayed linear order**: эта команда заменяет весь набор `after` последовательной цепочкой. Проверка типов и чтения ресурса до его первого производителя остаётся обязательной даже после этой команды.

Canvas показывает внешние ресурсы и реальные порты descriptors. Связь назначает именованный ресурс входу. Input читает последнее предшествующее значение этого ресурса в авторском порядке; ReadWrite затем публикует новое. Это граф именованных ресурсов, а не отдельная сохранённая копия каждой линии. Для независимых значений заведите разные ресурсы. Несовместимые типы, отсутствующие порты и попытка соединить выход с более ранним узлом отклоняются.

Custom Rust участвует в этом графе через обязательные world/input/events: GameWorld ReadWrite, GameInput Read, GameEvents ReadWrite. `params.source_id` выбирает исходник; `params.components` добавляет имена компонентов, которые этот исходник использует. После успешного Apply их сохранённые поля появляются в обычном инспекторе. Эти связи не означают, что весь Rust-код уже представлен визуальными операциями.

Выбранный узел показывает params JSON и списки совместимых ресурсов для каждого binding. **Update draft params** обновляет только черновик. Полный текст `ExecutionGraph` находится в **Text graph: resources / stages / bindings / params**. Здесь доступны `initial`, все bindings и after. **Load JSON into draft** синхронизирует текст с визуальным черновиком. Пока изменённый текст не загружен, общее Apply отключено: редактор не применит старый граф вместо введённого текста.

~~~json
{
  "resources": [{"name": "input", "data_type": "GameInput", "external": true, "initial": null},
                {"name": "world", "data_type": "GameWorld", "external": true, "initial": null}],
  "stages": [{"name": "Controllers", "nodes": [{"id": "controller", "module": "game.input",
    "params": {}, "bindings": {"input": "input", "world": "world"}, "after": []}]}]
}
~~~

Изменения сначала живут в локальном черновике: можно временно отсоединить обязательный pin, переименовать ресурс или перестроить несколько узлов. **Apply graph draft** проверяет весь граф, исходные сцены и возможность создать кандидат исполнения. Только успешный кандидат заменяет документ и runtime. Неверный кандидат остаётся редактируемым, предыдущий граф продолжает работать. **Discard draft** возвращает сохранённый граф. Save/Export требует применить или отменить черновик перед продолжением; незавершённый черновик не сохраняется между запусками редактора. Открытие другого проекта и выход учитывают его как несохранённую работу.

Undo/Redo, применение JSON, checkpoint и merge не заменяют документ поверх незавершённого Gameplay Systems. Сначала выполните **Apply graph draft** или **Discard draft**. Save проверяет наличие этого черновика до применения JSON, чтобы другой граф не уничтожил несохранённую работу.

Координаты canvas — личные настройки, записываются отдельно в `.user/full/game-systems-positions.json`; в игровой ExecutionGraph они не входят.

## Rust Custom во время Play

Выберите подключённый `source_id` и нажмите **Apply selected game Rust**, либо используйте обычное Apply в Rust-редакторе. Компиляция идёт в фоне; действующие экземпляры продолжают работать. Совместимое состояние сохраняется. При несовместимой schema доступен явный **Apply rejected version + reset its state** или JSON-панель **Apply version with migrated state**. Введённое состояние применяется ко всем экземплярам выбранного source ID после проверки новой версии; при отказе остаётся предыдущий runtime.

## Проверка авторских действий

`cargo test --locked -p module-engine-editor game_ui::tests` проверяет копирование сцены, создание связанного шаблона, overrides после сохранения/повторного чтения, сохранение неактивных данных и tint при назначении текстуры, восстановление отсоединённого typed pin и запрет неверного порядка. Headless egui-тест рисует реальный graph UI с неполным черновиком и проверяет, что сохранённый документ остаётся неизменным. Это проверка поведения UI, без заявления о визуальном качестве всех размеров окна.
